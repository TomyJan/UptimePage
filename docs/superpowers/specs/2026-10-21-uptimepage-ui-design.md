# UptimePage：已确认的页面设计

日期：2026-10-21。用户已确认 A 精进原型，可进入正式实现准备。

本文保留页面设计约束；当前部署、配置和来源能力以[使用文档](../../../README.md#文档)为准。

视觉基准：[原型 HTML](../../../design/prototypes/refined-a.html)，确认时提交为 `4d313b1`。前序约束见[需求与基础架构](2026-10-20-uptimepage-foundation-design.md)；原型入口、参考来源及许可见[设计说明](../../../design/README.md)。

本文件固定页面结构、视觉与交互。原型的模拟数据、固定数量、取数实现、工具栏和示例百分比不进入生产实现。以下数据口径与空态细化是实施准备中的设计决定，遵守前序“不伪造数据”的约束。

## 1. 页面与信息

### 首页

顺序为：导航、页面标题与刷新入口、大分组、状态摘要、子分组与搜索、监控列表、页脚。

- 首次进入选择配置中的第一个大分组及其“全部”；切换大分组回到“全部”。
- 大分组、子分组各自显示配置的名称、数量和独立 Logo；自动生成的“全部”不需要用户配置。
- “全部”只在当前大分组内去重、合并，不按子分组再切成若干列表。
- 摘要显示当前大分组的总体状态和正常、故障、其他数量，不随搜索结果改变。
- “异常优先”按钮紧接摘要文字，不再单独占据一行；初始值取站点配置。实施决定：按上次观测状态置顶故障、重试中和未知的条目，同一等级保持原顺序，维护和暂停不默认置顶。
- 搜索按当前子分组中的名称与明确配置的公开描述过滤，不搜索或暴露上游私有配置。
- 瘦长行卡显示：Logo、名称、可选公开描述、状态、最近 24 小时历史、24 小时可用率、最新响应、进入详情的箭头。
- 原型里的域名行在正式版使用显式配置的公开描述；不自动把上游目标地址作为公开描述返回。
- 数量随真实结果变化，不以 10 / 50 条为限制；空分组、搜索无结果分别显示简短空态。
- 页脚左侧固定显示 UptimePage、构建提交短 hash 与 TomyJan 链接，右侧显示用户配置；不重复语言、时区、主题或更新时间。

### 详情

- 路由采用 `/services/:groupId/:monitorId`，与子分组和显示名称无关。直接访问、刷新与返回均可用。
- 窄屏（不超过 800 px）返回与刷新控件共用顶部操作行；下方展示 Logo、名称和描述，状态紧跟名称，空间不足时自然换行。宽屏保留返回独占上行、服务信息与状态及刷新控件同排的布局。加载态沿用对应屏宽的布局。
- 标题显示 Logo、名称、可选公开描述和当前状态；首次取数失败显示脱敏原因，刷新失败通过 Toast 提示。
- 四项指标：所选范围可用率、最新响应及其检查时间、所选范围平均响应、证书剩余时间。
- 响应趋势支持 24 小时、7 天、30 天三个范围，按来源实际能力提供；不支持的范围禁用并给出简短原因。
- 检查历史和近期事件跟随所选范围；服务信息显示类型、自动换算单位的检查周期、来源和精确到秒的最后检查时间。
- 只展示上游真正提供的事件与证书信息；无事件数据不能冒称“暂无故障”，无证书不能显示“0 天”。
- 证书可用时显示剩余天数和到期时间，过期显示“已过期”。近期事件列表自然收缩，桌面最大 360 px、手机最大 300 px，超出后内部滚动，标题不滚动。
- 从列表进入后返回保留所在大分组、子分组和搜索；直接打开详情后返回该大分组的“全部”。
- 不在公开范围的条目显示不可用页面，不能通过已知 ID 绕过服务端检查。

## 2. 视觉与响应式

- 采用鸢尾主题，中性底色和卡片；品牌浅色 `#5266eb`、小字交互 `#4558d4`，深色强调 `#a5b1ff`。完整色值以原型的 CSS 变量为基准。
- 正常历史条固定使用 `#4b9d71`，深浅色和品牌设置不改变其语义。故障、提醒、维护各自使用独立语义色；无数据为空心条。
- 卡片圆角约 16 px、摘要 18 px、菜单 14 px；轻阴影和细边线保持层次，避免大面积品牌色染底。
- 桌面保留多列行卡。宽度不超过 800 px 时，行卡变为名称 / 状态、历史、指标三行；子分组和搜索分行。
- 最窄验证宽度为 320 px，并覆盖手机横屏；名称截断、长描述、任意数量的分组不能造成全页横向滚动。
- 文案只保留字段、状态、必要操作和异常原因，不添加宣传句、重复标题或解释性段落。

## 3. 导航、菜单与回顶

- 导航固定在视口顶部，并保留等高的正文空间。向下滚动逐步收起，向上滚动逐步展开；停止后平滑收束，到顶完整显示。
- 快速反向滚动从当前动画位置继续，不跳回旧目标；忽略滚动回弹，不误判方向。
- 导航包含语言、时区、深浅色三个弹出菜单；遵守浏览器偏好、英文 / UTC 回退和本地持久化规则。
- 下拉使用统一的自定义弹层，不能用浏览器原生 `select`；支持方向键、Esc、点击外部关闭和焦点恢复。
- 菜单交替打开时旧面板退出、新面板从各自锚点进入；滚动时关闭浮动菜单和数据提示。
- 上翻且未到顶部时，右下角出现圆形箭头回顶按钮；停止后保留，下翻或到顶时消失。
- 回顶按钮使用相同表面、阴影、强调色和动效，层级高于 Toast；出现时通知向上平滑让出位置。
- 点击平滑回顶；系统减少动态效果时直接到顶。按钮隐藏后不能保留在键盘焦点顺序中。

## 4. 刷新与通知

- 刷新与“更新于”合成分段按钮：点击时间区域手动刷新，点击箭头打开频率菜单。
- 菜单提供跟随站点、仅手动、每 30 秒、每分钟、每 5 分钟。站点默认由配置决定，访客覆盖保存在浏览器。
- 实施初始默认值为 60 秒，`0` 关闭自动刷新；这是浏览器取本站数据的周期，不等于上游请求周期。服务端缓存与预算另行制定。
- 自动模式显示倒计时，刷新时图标旋转且主按钮暂时禁用；手动完成后重新倒计时，不并发发起重复请求。
- 只请求当前页面所需数据；隐藏页面暂停自动轮询，恢复时过期只补一次。刷新、自动更新和重试均提供结果 Toast，不重播页面或图表入场动画。
- “更新于”指最近成功取得本站快照的时间；失败保留旧数据和旧时间，不添加重复的过期提示。最后检查时间来自上游，不能用请求完成时间替代。
- Toast 采用透明、穿透点击的浮层；卡片各自有背景、圆角、边线、阴影及关闭图标，外层没有背景、限高或滚动容器。
- 最多显示 5 条，短屏按空间进一步减少。最新消息从下方进入，旧消息向上移；放不下的旧消息退出并销毁，不排队、不补回。
- 每条通知单独计时；悬停、键盘焦点或页面隐藏时暂停，关闭或挤出时清理计时器和动画。
- 通知支持深浅色和中英文，不抢夺焦点；正在聚焦的旧消息被挤出时，焦点转移到仍存在的可用控件。

## 5. 图表、历史与数据缺失

- 正常 / 故障等监控状态与新鲜 / 过期 / 无数据的获取状态分别记录，API 失败不自动变成监控故障。
- 摘要和状态徽标展示最近一次取得的监控状态；取数失败不改写观测状态，更新时间保持不变。首次没有数据时不显示正常状态。
- 缺失数值显示 `—`，不填零；确有 0 ms 或 0% 的上游值仍按真实值显示。
- 历史条按真实覆盖区间汇总，最多 48 块；稀疏聚合采样使用更宽时间块。未覆盖区间留空，不用当前状态补造历史。
- 不补造缺失采样；响应图按实际检查周期分段绘制。最多缺少一次检查的短缺口用虚线标记，长缺口与故障保持断开。有效段使用保留采样点的单调三次插值，不制造额外峰谷。
- 图表使用实际宽度重算坐标，统一纵轴与曲线映射；裁切揭示绘制，右端点必须完整，不使用虚线描边模拟进度。
- 平均响应必须来自上游汇总或具有明确口径的真实采样；不能用“最新响应 + 常数”生成。
- 可用率保留周期、覆盖范围与来源口径，不跨来源直接平均；没有足够依据时显示缺失。
- 悬浮历史条或可用率立即显示自定义提示；连续移过条块同步更新，支持手机点按与键盘浏览。禁止浏览器原生 `title` 提示。

## 6. 动效与可访问性

- 动效沿用原型节奏：子分组约 360 ms、列表约 440 ms、页面约 520 ms、图表约 1450 ms；Toast 进入 / 重排约 320 ms、退出约 200 ms。
- 主题切换、刷新、列表重排和悬停互不覆盖；快速操作以最后选择为准，不残留旧弹层和过渡快照。
- 尊重 `prefers-reduced-motion`；没有页面过渡 API 时退化为局部淡入，功能不受影响。
- 保留跳过导航、可见焦点、语义 Tab / switch、菜单键盘操作和必要的屏幕阅读器通知。
- 历史交互控件与进入详情的链接分别提供语义，正式 React 结构不能沿用原型中的嵌套交互元素。

## 7. 正式实现中的必要补充

这些场景在原型中不完整，按既定布局补充，不另选视觉方向：

| 场景               | 行为                                         |
| ------------------ | -------------------------------------------- |
| 首次加载           | 保留页面结构，显示轻量骨架；不闪出“全部正常” |
| 刷新失败且有旧结果 | 保留卡片和更新时间，Toast 展示脱敏原因       |
| 首次获取失败       | 错误空态和重试入口，不生成假服务             |
| 部分成功           | 成功条目可用，失败部分独立标记               |
| 无历史 / 不支持    | 留空或显示简短原因，禁用无能力的范围         |
| 配置没有分组       | 构建时报配置错误；运行时未知路由显示不可用   |
| 监控移出公开范围   | 清理相关前端缓存，详情立即停止展示返回的数据 |

## 8. 实施分段

1. 正式前端：构建配置校验、统一类型和 API 客户端，组件化还原页面；使用明确标记的本地模拟数据验收。
2. 真实取数：Peekaping、UptimeRobot、公开范围检查、缓存及可选 KV；各适配器单独验证分页、口径、限流和缺失能力。
3. 集成上线准备：接真实接口，检查构建产物隔离，在 EdgeOne 预览环境验证路由、函数和降级。正式发布另行执行，不把本地测试当作平台验证。
