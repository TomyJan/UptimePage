# 排错

## 常见问题

| 现象                             | 检查                                                                                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 仍请求原站点 / 示例来源          | `config/site.json` 是否替换并提交到部署分支，是否被 `UPTIMEPAGE_CONFIG` 覆盖，最新部署是否生效              |
| 配置构建失败                     | JSON 格式与错误中的字段路径；配置完整替换，损坏时不会回退默认文件                                           |
| API 返回 HTML                    | 云函数是否部署、API 路由是否被 SPA fallback 接管；仅上传 `dist/` 不够                                       |
| 获取失败 / 502                   | 函数能否读取 `apiKeyEnv` 指定密钥，来源地址、状态页权限和来源接口版本是否正确；结合 `diagnostic` 定位       |
| 545 / `Error return from script` | 平台启动或执行中止可能发生在函数捕获范围外；记录时间、请求 ID 及 `X-NWS-LOG-UUID`（若有），核对平台调用记录 |
| 429                              | 上游额度和退避截止时间；手动刷新不会解除退避，旧数据与更新时间应保留                                        |
| 历史不完整 / 没有证书            | 上游套餐、保留期、检查周期及 TLS / SSL 接口能力；本站不补造采样，也不主动扫描目标                           |
| 编辑器不出现                     | 构建时是否精确设置 `UPTIMEPAGE_CONFIG_EDITOR=true` 并重新部署，URL 是否带 `configeditor=on`                 |
| 编辑器修改未生效到生产           | 需导出 `site.json`，提交到自己的部署分支并重新部署；预览不保存到服务端                                      |
| 验收缺少资源 / 配置版本不符      | 本地与部署的提交、配置、锁文件和构建变量是否一致，包括编辑器开关                                            |
| KV 无记录                        | 项目资源绑定及 `cache.kvBinding` 是否一致；绑定后重新部署并访问 API，不能把命名空间 ID 当绑定变量名         |

## 错误与耗时

API 的 `diagnostic` 只返回固定原因、HTTP 状态和阶段，不返回上游正文、地址、密钥或堆栈。检查接口响应及刷新失败 Toast；错误结构见[HTTP 接口](data-api.md#http-接口)。

| 响应头                         | 含义                                                                                                          |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| `Server-Timing`                | `total` 总处理时间；`membership` 成员确认；`snapshot` 整组取数；`detail` 详情；`cache` 累计缓存等待，单位毫秒 |
| `X-UptimePage-Source-Requests` | 本次发起的来源请求数                                                                                          |
| `X-UptimePage-Cache`           | 云函数访问缓存桥的操作结果和脱敏 origin 指纹                                                                  |
| `X-UptimePage-Cache-Bridge`    | 缓存桥拒绝原因                                                                                                |

计时阶段可能重叠，不能直接相加。来源请求数为 0 仅能说明本次未请求来源，不代表所有节点都已命中缓存。云函数还输出 `uptimepage.request` JSON 日志，仅含状态码、耗时和请求数；平台能否检索业务日志取决于其开放能力。

## 缓存桥诊断

`X-UptimePage-Cache` 中，`status` / `membership` 为状态 / 成员缓存，`match` / `put` 为读取 / 写入。

| 结果                  | 含义                                           |
| --------------------- | ---------------------------------------------- |
| `http-200`            | 桥接请求成功；是否使用 KV 仍需核对命名空间记录 |
| `network` / `timeout` | 连接失败 / 超时，自动降级                      |
| `pending`             | API 返回时缓存操作尚未完成                     |
| `oversized`           | 超过桥接报文限制，跳过共享写入，仍可用实例缓存 |
| `http-404`            | 缓存桥拒绝请求，后续标签标明阶段               |
| `unconfigured`        | 未能从运行时来源密钥派生缓存签名               |

404 阶段标签：`configuration` 为缺少运行时配置，`signature` 为验签失败，`crypto` 为加密接口异常，`version` / `origin` 为版本 / 来源不匹配，`expired` 为签名过期；其他标签对应报文、路径、写入值或内部处理错误。

`origin-` 后 12 位为缓存目标 HTTPS origin 的 SHA-256 前缀；`host-`、`x-forwarded-host-`、`eo-pages-host-` 同样为脱敏指纹。云函数使用平台覆盖的 `eo-pages-host` 恢复公开域名，不采信通用转发头；正常请求中，`origin-` 应与 `eo-pages-host-` 一致。

缓存桥 HTTP 200 不保证节点 Cache API 可写。节点缓存拒绝、KV 不可用时仍可实时取数；若需要跨实例回退，按[KV 配置](configuration.md#可选-kv)绑定并核对实际记录。
