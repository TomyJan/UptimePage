# 发布检查

## 本地与 CI

- 执行[开发文档](development.md#验证)中的格式、类型、测试、构建隔离及依赖审计。
- 核对 `UPTIMEPAGE_CONFIG` 的配置版本；GitHub 代理失败应回退直连，所有尝试失败必须中止构建。
- 核对手机 / 桌面、中英文、深浅色、键盘操作和减少动画偏好；加载与正常态保留同一布局。
- 浏览器静态产物默认不含编辑器或演示数据；关闭 / 开启编辑器均不包含实际来源地址、选择规则或密钥变量名。
- 编辑器的表单、JSON、导入导出使用同一份校验；预览不访问生产监控 API，退出后恢复真实数据。

## 部署

使用与部署一致的提交、配置、锁文件和构建变量，执行[部署验收](deployment.md#部署验证)，并核对：

- 首页一次加载当前大分组，子组切换不重复取数；数量、排序和公开范围符合配置。
- 双来源详情的 24h / 7d / 30d、检查时间、周期、事件和证书符合上游能力与数据。
- 监控链接按全局 / 分组 / 子组继承；首页和详情只显示允许公开的链接，新标签页打开。同一监控跨子组时分别核对“全部”和具体子组。
- 自动图标只请求本站加密地址；手动 Logo 优先，失败保留文字，不拖慢首页聚合。
- 深层路由刷新、返回、手动 / 自动刷新及错误 Toast 正常。
- 旧动态资源失效时，确认有新版本才自动恢复；同版本不循环刷新。编辑模式保留草稿，仍可导出。
- 编辑器仅在启用构建且带 `configeditor=on` 时出现；Umami 按部署配置加载，包括编辑会话。
- 隐私政策可从页脚及提示文本进入；中英文、深层路由和切页层级正常，确认提示后刷新不再显示，禁用存储时仍能关闭。窄屏下不遮挡通知及必要操作。
- 启用 KV 时，绑定空间中出现对应的新记录；页面可用或 HTTP 200 不能单独证明 KV 命中。

## 故障与性能

来源适配、鉴权或缓存变更后，在独立预览环境检查：

| 场景                     | 预期                                              |
| ------------------------ | ------------------------------------------------- |
| 未绑定 KV / KV 故障      | 自动降级，实时取数仍可用                          |
| 来源故障或限流，有旧快照 | 保留数据及更新时间，返回脱敏原因和重试时间        |
| 冷缓存且来源故障         | 返回脱敏错误，来源恢复后可重新取数                |
| 来源状态页撤销成员       | 名单缓存到期后移除，详情缓存不能绕过新公开范围    |
| 修改配置或更换密钥       | 不复用旧配置 / 旧凭证缓存；移除密钥后返回配置错误 |

分别记录冷 / 热请求的 `Server-Timing`、来源请求数与平台调用记录。Peekaping 冷请求量随监控数增长，UptimeRobot 长周期查询受来源保留期和额度限制。缓存能力与诊断见[数据与接口](data-api.md)和[排错](troubleshooting.md)。
