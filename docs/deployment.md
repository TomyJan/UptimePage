# EdgeOne 部署

## 1. 准备

- 在 Peekaping 建好公开状态页，记录别名；在 UptimeRobot 记录要公开的监控 ID。
- 修改[配置](configuration.md)。示例地址和 `example-1` 等占位 ID 不能直接用于生产。
- 在 EdgeOne Makers 导入仓库，项目根目录使用仓库根目录。

`edgeone.json` 已设置 Node 版本、`pnpm install --frozen-lockfile`、`pnpm run build` 和输出目录 `dist`。pnpm 版本由 `package.json` 的 `packageManager` 决定，不在命令中另写版本。

不要只上传 `dist/`：还需要平台从仓库部署 `edge-functions/` 及其导入的源码、生成配置。安装和构建日志必须成功，函数应生成 `/api/v1/*` 路由。

## 2. 服务端变量

在 EdgeOne 服务端函数环境中设置 `apiKeyEnv` 对应的值，默认是：

| 变量 | 值 |
| --- | --- |
| `PEEKAPING_API_KEY` | 对应 Peekaping 实例的 API Key |
| `UPTIMEROBOT_API_KEY` | 能读取选中监控的 UptimeRobot Key |

有多个连接时可以使用不同变量名。只需配置实际使用的来源。不要把密钥写入 JSON、提交到 Git，或设置成 `VITE_*`。更新变量后按平台要求重新部署，确认函数取得新值。

KV 可选，按[配置说明](configuration.md#可选-kv)绑定；首次部署建议先不启用。

## 3. 预览验收

部署到预览环境后，本地检出**部署的同一提交**，使用相同配置、锁文件及构建变量运行检查；如果部署设置了 `UPTIMEPAGE_COMMIT`，本地也使用同值。命令会比对构建资源，配置相同但提交不同也会产生不同哈希。它不需要来源密钥，只访问本站公开页面和接口。

PowerShell：

```powershell
$env:UPTIMEPAGE_PREVIEW_URL = 'https://your-preview.example.com'
# 如果部署用了自定义配置，再设置 UPTIMEPAGE_CONFIG；默认配置无需设置。
pnpm run verify:deployment
```

sh：

```sh
UPTIMEPAGE_PREVIEW_URL=https://your-preview.example.com pnpm run verify:deployment
```

使用不带路径的 HTTPS 地址。命令先构建本地同配置产物，再检查：

- 首页及 HTML 引用的脚本、预加载、CSS，还有本地构建的详情等 JS / CSS 分块，均返回正确类型；API 没被 SPA fallback 变成 HTML。
- 每组返回新鲜、完整的数据，配置版本与本地相同。
- 每组抽查一个详情、深层页面直达和错误参数。
- 未知组、未知监控被拒绝；已存在组和详情拒绝 POST / PUT / PATCH / DELETE，API 使用 `no-store`。

非零退出码表示失败。空组的详情检查显示 `SKIP`，不能当作已验证。命令遇到限流会失败；不要连续高频运行，等待来源退避后再试。

## 4. 平台检查

自动检查通过后，仍需在预览环境完成：

- 对照上游确认监控数量、状态、延迟、历史范围，尤其是窗口之前开始但仍在持续的 UptimeRobot 故障。
- 浏览器直接打开详情、刷新和返回；确认简中 / 英文、手机、深浅色正常。
- 在控制台确认函数 CPU、错误和上游请求量，覆盖约 50 个监控及多访客并发。节点间不共享在途请求，不能以本地合并次数推算全站额度。
- 用测试来源或测试分组制造限流 / 不可达，确认旧数据标旧、首次失败显示不可用、自动刷新遵守退避，恢复后能更新。
- 若启用 KV，分别验证已绑定、未绑定、存储不可用时的行为；检查节点缓存清除后能否使用 KV。不要为验收破坏生产命名空间。
- 关闭自动刷新，5 分钟后确认快照标旧；手动刷新成功后恢复。

没有实际执行这些项目，就不能称为“平台验收完成”。本地测试使用受控来源响应，无法验证套餐、网络和 EdgeOne 节点行为。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| API 返回 HTML | 函数是否被部署、路径是否匹配；只上传 `dist` 无法提供 API |
| 获取失败 / 502 | 函数环境变量、来源地址、状态页权限和版本；不要将真实错误或密钥公开输出 |
| 配置版本不一致 | 本地与平台是否使用同一份配置，最新构建是否已生效 |
| 构建资源缺失 | 先确认本地与部署的代码提交、配置和构建变量相同，再检查资源是否上传完整 |
| 历史只有一小段 | Peekaping 状态页只提供最近心跳；UptimeRobot 历史受套餐限制 |
| 没有证书 / 7 天 / 30 天 | 当前适配器未接入这些能力，显示缺失是预期行为 |
| KV 没命中 | `kvBinding` 名称、平台绑定、快照版本和截止时间 |

## 更新与回退

更新代码或配置后重新构建并在预览验收，再按平台流程发布。回退时回退完整部署（静态页面和函数一起），避免配置版本不一致。KV 过期记录不会被读取；EdgeOne KV 无原生 TTL，已删除路由的槽位可在控制台手动清理。
