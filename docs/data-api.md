# 数据与接口

## 来源能力

| 内容               | Peekaping                                               | UptimeRobot                                                        |
| ------------------ | ------------------------------------------------------- | ------------------------------------------------------------------ |
| 公开范围           | 配置状态页列出的监控 ID                                 | 配置 ID，或 `*` 选择密钥可读的全部监控                             |
| 名称、状态、周期   | 鉴权监控批量接口                                        | 上游监控配置                                                       |
| 首页响应时间       | 鉴权接口的最近心跳延迟                                  | 最近 30 分钟聚合采样均值                                           |
| 详情曲线、检查历史 | 鉴权统计接口；24h 按分钟 / 检查周期，7d、30d 按小时聚合 | 24h 原始采样，7d / 30d 按 30 / 60 分钟聚合，含故障日志；受套餐限制 |
| 可用率             | 鉴权接口的所选范围统计                                  | 上游 1 / 7 / 30 天统计                                             |
| 近期事件           | 鉴权心跳接口，分页读取状态转换                          | 故障日志                                                           |
| 证书               | 鉴权 TLS 接口的叶证书到期时间                           | 详情请求 `ssl=1` 返回的到期时间；取决于来源提供的数据              |

支持 `24h`、`7d`、`30d`，首页固定 24 小时。UptimeRobot 单次响应时间查询最多 7 天，30 天按最多 7 天分段串行读取并合并，故障日志和周期可用率只查一次；任一段失败会保留旧数据并报错。上游套餐或保留期限可能缩短实际历史；图表始终保留所选时间轴，未取得的区间留空。状态页接口**只用于分组成员 ID**，不采用其中的名称、状态、可用率或历史。实际数据全部使用服务端 API Key 查询，并只返回公开字段；密钥、目标地址和私有配置不会返回浏览器。

证书只在详情获取，不新增站点检查任务。Peekaping 与历史并行请求 `/monitors/:id/tls`，读取 `data.certInfo.validTo`；旧版无该路由显示不支持，其余错误或空结果显示无数据，不影响状态和历史。UptimeRobot 复用主详情请求的 `ssl.expires`（Unix 秒），历史分段、首页和最新检查补查不重复查询证书。浏览器只收到到期时间与能力；有值时显示剩余天数、到期时间，过期显示“已过期”。不会主动连接监控目标读取 TLS。

检查历史以最多 48 个时间块汇总该时段的检查结果，稀疏聚合采样使用更宽的时间块；异常优先，混合结果显示部分异常，无记录时段留空。时间块不表示持续在线。缺失值显示 `—`，真实零值显示 `0`；曲线按实际周期连线；最多缺少一次检查的短缺口使用虚线，长缺口与故障仍断开，不补造采样。故障日志优先于响应点。不平均不同来源的可用率。

UptimeRobot 的窗口筛选会漏掉窗口前开始的故障。遇到持续故障且窗口无转换，或窗口第一条为恢复记录时，按监控批量补取最近日志：数量为已知窗口记录数加一，只合入窗口前的最后一条，不重复查询响应曲线和可用率。补取失败或监控状态已变化时按来源失败处理，避免发布不完整结果。可用率保留上游统计，不用响应采样推算替换。

## 读取与缓存

公开 API 在 EdgeOne Cloud Functions 中聚合；边缘函数只读写缓存，不请求监控来源。云端通过绑定站点、配置版本和 60 秒有效期的 HMAC 请求访问边缘缓存，签名使用已有来源密钥派生。缓存传输响应始终 `no-store`，未签名请求返回 404。

- Peekaping 成员名单按子组独立缓存 **10 分钟**，先读实例内存，再读节点缓存 / 可选 KV；只保存 ID，子组并行读取且保持配置顺序。到期必须重新获取，失败的子组不沿用过期名单，也不能授权详情。撤销最迟在名单缓存到期后生效，不保证跨节点瞬时同步。
- 状态和详情缓存新鲜期 **30 秒**。可选 KV 和节点缓存保留成功数据最多 5 分钟。状态 / 详情与成员名单并行读取，使用前校验期限、配置版本和内部名单代次；旧名单对应的缓存不能绕过新名单。配置变化会隔离旧缓存，名单代次不进入公开响应。
- 首页一次请求返回当前大分组的全部卡片数据，子组切换在本地完成；不预取其他大分组或逐项请求详情。Peekaping 批量读取监控配置（每批最多 100 项），最多 16 项并行调度近 24 小时的小时统计和最近一条检查，实际来源连接最多 16 个；快心跳完成后空出的连接可用于后续统计。首页不读取事件分页、证书和分钟曲线。UptimeRobot 按 50 项分页批量取 24 小时统计、30 分钟均值和故障日志。
- 详情页按时间范围独立查询、缓存，只获取当前监控的历史。授权与展示数据分开，冷加载详情不会触发全组历史；可复用新鲜首页的监控信息及同一实例中的在途首页查询。
- 同一云函数实例合并重复请求，并使用有界内存缓存（最多 16 MiB / 256 项，单项最多 2 MiB）。共享缓存命中会回填较快的缓存层，暖实例无需重复访问缓存桥；读取数据时仍检查原始时间，不延长新鲜期和授权期限。跨实例不做全局锁，仍受上游额度限制。
- 每个来源域名在同一云实例中最多 16 个在途来源请求，配额覆盖响应体读取；多个分组和访客共享上限。Peekaping 在本次聚合取得调度名额后启动 4 秒请求计时，云实例共享连接池的等待仍计入此预算；本次聚合排队不会吃掉健康请求的执行时间。首页遇到超时、网络故障或限流后取消排队和在途伙伴，停止派发后续项，失败结果不冒充新快照。任一并行配置批次失败后不继续领取批次。
- 缓存损坏、超时、未绑定或故障均可降级，不依赖 KV 原生 TTL。签名缓存请求超过边缘函数 1 MB 上限时跳过共享写入，使用实例缓存；缓存不影响公开读取权限和实时取数。
- 刷新、自动更新和重试均提供结果 Toast，失败显示脱敏原因及可用的 HTTP 状态。已有完整快照时保留它及其更新时间，直到整组成功；确认撤销的监控和详情缓存会立即移除。
- 首次部分失败可显示已取得的数据。限流退避随错误传给前端，手动刷新不提前解除退避。API 对浏览器 / CDN 返回 `no-store`，由函数管理缓存。

Peekaping 0.0.47 没有鉴权批量统计 / 心跳接口。名单缓存命中时，40 项完整首页仍需约 81 次来源请求（一次批量配置及每项两个请求）；本地测试的并发耗时不能当作生产响应时间保证。

## HTTP 接口

接口公开只读，不需要浏览器传密钥；服务端只返回公开展示字段，不透传上游配置或错误。浏览器不能指定上游地址或凭证。

```text
GET /api/v1/groups/:groupId
GET /api/v1/groups/:groupId/monitors/:monitorId?range=24h|7d|30d
```

`periodUptime` 和 `averageResponse` 对应所选范围，`monitor.uptime24h` 始终保留首页的 24 小时口径。最新响应显示实际检查时间，时间显示到秒；检查周期自动换算为天、小时、分钟、秒。

首页使用 `home-v1` 精简契约（[home.ts](../src/shared/home.ts)）：每项历史为最多 48 个等宽 `[状态, 响应毫秒或 null]`，时间范围统一由 `fetchedAt` 向前 24 小时推导；分组身份、子组归属和可用率时间范围不在每项中重复。响应毫秒保留两位小数，省略详情专用字段。浏览器解码后仍使用统一展示模型。

详情结构见 [contracts.ts](../src/shared/contracts.ts)。时间使用 UTC ISO 8601，页面按访客所选时区显示。错误格式：

```json
{
  "error": {
    "code": "unavailable",
    "retryAt": null,
    "diagnostic": { "reason": "upstream-http", "status": 403, "stage": "source" }
  }
}
```

| 错误码             | HTTP | 含义                                |
| ------------------ | ---- | ----------------------------------- |
| `not-found`        | 404  | 未公开、不存在或不支持的路由 / 方法 |
| `unavailable`      | 502  | 来源或服务端配置不可用              |
| `rate-limited`     | 429  | 来源限流，`retryAt` 可给出重试时间  |
| `invalid-response` | 502  | 参数无效或响应不满足契约            |

`diagnostic` 可选，仅包含固定原因、HTTP 状态和处理阶段，不包含上游正文、地址、密钥或异常堆栈。原因包括缺少凭证、来源拒绝、超时、网络故障、格式错误及内部异常。首次加载显示原因，刷新失败通过 Toast 展示。平台在函数外强制中止或启动失败无法被函数捕获；浏览器对非 JSON 的 HTTP 545 显示边缘函数执行失败。
