# 第一阶段验收

2026-10-21，正式前端已实现。页面采用已确认的 A 原型布局与鸢尾主题，开发演示独立于生产客户端。尚未接入真实来源或部署到 EdgeOne。

## 已验证

- 42 项单元测试：配置隔离、数据契约、偏好回退、请求与缓存、刷新调度、分组顺序、历史缺口、曲线和通知。
- 40 项浏览器测试：页面与菜单、生产 HTTP 错误、首次限流、刷新失败、滚动与通知、无页面过渡 API、减少动态效果和多尺寸截图。
- 首页与详情截图：1440、768、390 px × 中英文 × 深浅色；另检查 320 px 与 568 × 320 横屏。
- 人工对照已确认原型：布局、层级、圆角、阴影、固定绿色、曲线端点及浮层。
- `typecheck`、生产构建、格式检查与私有哨兵扫描通过；即使生产构建设置 `VITE_DEMO=true` 也没有演示数据。
- 本地 Node 引导命令返回 `v22.21.0`。EdgeOne 平台的安装、网络、路由与函数仍需后续预览验证。

浏览器测试使用本机已有 Chromium，通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定；其他环境可按开发说明安装 Playwright Chromium。截图位于被忽略的 `test-results/`，不作为已建立跨平台像素基线的声明。

## 实施决定

- 按已批准计划在 `master` 原子化提交，不推送、不部署；如需改用功能分支，提交仍可直接迁移。
- 详情契约增加可选公开 `sourceName`，用于显示来源名称，不包含连接地址；若后续契约需要调整，仅需重命名此字段。

## 下一阶段

真实来源适配、公开名单检查、缓存和可选 KV；随后在 EdgeOne 预览验证。当前默认生产模式未配置本站 API 时显示获取失败，不使用模拟数据代替。

## 独立审查与修复

完整实现经过一次独立审查，没有 Critical；修复了 10 项 Important，并把两项会误导状态判断的 Minor 升级后一并修复：

- 撤销详情时同步清理所在组的监控与子组引用，保留其他组的同 ID 条目；拒绝组身份、配置版本或监控归属不匹配的响应。
- 详情首次失败保留刷新调度；范围失败保留页面与范围选择，局部提示错误，不把旧曲线当作新范围数据。
- 触屏提示支持展开、再次点击关闭、外部点击及 Esc；密集历史条按真实时间比例缩小间距；长描述正常换行。
- 通知被替换后在 DOM 提交完成再恢复焦点，跳过禁用控件。
- 历史时间按时间戳校验；详情可用率说明真实覆盖范围；可识别的单次缺失采样断开曲线；时间轴与曲线使用同一排序。
- 不可用采用中性色，重试中采用提醒色，避免被误认为正常。

每项修复都有先失败后通过的回归用例；仅因测试环境时区、子像素舍入或定位器歧义造成的失败先修正测试，再验证实际缺陷。

## 本轮裁决及延后项

- 真实来源鉴权、分页、能力映射、服务端公开名单、缓存及 KV 留到第二阶段，避免在前端目标中引入未验证后端。若判断有误，接入时需调整契约。
- EdgeOne 安装、网络、函数优先级和平台缓存留待平台预览验证。若判断有误，发布前需补平台兼容修复。
- 本轮不自行添加浏览器数据 TTL。缓存阶段必须明确新鲜期截止规则；当前返回旧页面可能先显示旧快照，直到下一次刷新。这一限制需要在真实上线前解决。

延后的 Minor：禁用范围缺少原因说明；图表旁未标注当前时区。原 `engines.node` 的 22.12 下限问题已在后续 pnpm 迁移中修正为 `^22.18.0`，EdgeOne 改用 `nodeVersion` 字段选择版本；当前开发方式见[开发说明](development.md)。原验收使用 Node 22.21.0。

首轮完整浏览器验收曾出现菜单焦点断言失败。原用例未确认菜单接管键盘就发送 Esc；现先确认菜单内已有焦点，再检查关闭与触发按钮焦点恢复。增强后的用例连续 5 次通过，再执行完整验收。
