# 验证状态

截至 2026-10-21，`bea3f0a` 已部署到 [生产站点](https://status.tomys.top)。双来源接口与缓存桥验收通过，以下平台故障演练和数据对照仍未完成。

## 已验证

- 公开 API 使用 Cloud Functions 聚合，避免边缘函数单次 64 次 fetch 限制。浏览器首页保持一次请求，来源查询最多 4 项并发；Edge Functions 负责节点缓存与可选 KV。
- 修复云函数使用内部 Host 导致缓存桥请求失败的问题：从平台设置的 `eo-pages-host` 恢复公开 HTTPS 地址，严格校验域名，保留查询参数；不信任通用转发头。桥接继续校验签名、有效期、部署版本和缓存范围。
- 最新本地 **215 项单元 / 集成测试**通过；类型、格式、实际配置构建、公开产物隔离检查通过。此前 **62 项浏览器测试**通过，本轮后续修改仅涉及服务端。
- `bea3f0a` 线上 HTTP 验收 **19 项通过、0 项跳过、无 429 重试**：双来源完整精简首页、24h / 7d / 30d 详情、同版本资源、深层路由、公开范围、只读限制、未签名桥接请求拒绝和 `no-store`。此前验收曾遇到 UptimeRobot 429，按 `retryAt` 重试后完成；本轮通过不代表来源不会限流。
- Peekaping 首页 40 项，UptimeRobot 首页 50 项。一次 Peekaping 请求因子组超时回退到 40 项旧快照并返回超时诊断，不能将其描述为始终新鲜。UptimeRobot `cloud` 子组按用户要求留空，线上为 0 项；实际配置未改。
- 控制台确认 `UPTIMEPAGE_KV → tomys_status_cache` 的本轮新记录：Peekaping 首页 `fetchedAt` 为 **2026-10-21 09:09:46 UTC**，UptimeRobot 首页为 **09:01:06 UTC**（50 项、新鲜、无子组错误）；双来源详情也有修复后的新记录。缓存桥读写均实测 HTTP 200，不仅依赖旧记录或接口命中判断。
- 本地覆盖 50 / 200 项聚合、限流停止派发、权限撤销、部分失败恢复、1 MB UTF-8 边界、签名篡改 / 过期 / 跨版本 / 跨站重放，以及节点缓存挂起、KV 故障和来源离线回退。
- 线上桌面确认中文 / 英文、浅色 / 深色、自动刷新时间推进，页脚版本为 `bea3f0a`。手机及刷新 Toast 的完整线上交互仍待验收。
