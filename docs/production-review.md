| 无效响应当作空列表、失败误报 404 | 校验来源结构与分页，明确区分来源不可用和监控被移除 |
| 未实现的范围返回 24 小时数据 | 只接受 `24h`，其他范围拒绝 |
| 详情缓存绕过动态名单、无关查询放大请求 | 先检查组名单再使用详情缓存，规范缓存键 |
| 缓存没有真正旧数据期，读写失败影响接口 | 30 秒新鲜期、5 分钟保留期；错误、损坏和超时均按未命中处理 |
| 返回旧缓存或部分成功时丢失限流退避时间 | 保留来源重试时间，自动刷新继续遵守退避 |
| 限流期间手动刷新收到成功的旧数据，导致自动轮询提前恢复 | 成功响应仅清除已过期的退避；保留仍有效的来源截止时间 |
| KV 长键超限、无截止时间的坏数据可用 | SHA-256 键、严格信封校验，配置版本复用槽位但不复用内容 |
| 首页拉取全部原始采样超出边缘处理预算 | 首页请求上游 30 分钟聚合，详情按单个监控取原始采样 |
| 页脚构建 hash 未始终缩短，归档构建产生坏链接 | 显示短 hash、链接完整提交；无 Git 时链接项目历史 |
| 缓存未命中时，并发访客重复请求同一上游数据 | 同一运行实例合并组快照和详情的在途加载，按来源凭证、配置版本和规范路由隔离，完成后释放 |
| 单个 Peekaping 子组失败，让成功子组的实时状态也失效 | 列表和统计保留每个监控的新鲜度；整次刷新失败仍统一标旧，部分结果不能显示全站正常 |
| 高频故障历史处理逐项交叉解析时间，耗尽边缘 CPU 预算 | 合并故障区间后顺序扫描采样，保留故障优先、缺口及边界语义 |
| 仅手动刷新或标签页休眠后，浏览器快照一直表示实时状态 | 快照生成后 5 分钟自动标旧，覆盖返回缓存页与休眠恢复，不额外请求；新快照恢复 |
| 不支持的时间范围没有解释，图表时区不明确 | 自定义提示支持键盘与中英文，图表显示当前时区 |
| 部署检查遗漏 CSS、预加载和懒加载块，只读检查没有使用有效路由 | 检查全部构建 JS / CSS，并对已存在组和详情验证四种写方法被拒绝 |

## 验证方式

单元回归使用 Peekaping 上游 DTO 与 UptimeRobot 官方文档对应的响应格式，覆盖故障、缺口、名单撤销、分页、配置排序、限流、缓存期限及 KV 故障。另执行格式、类型、构建、公开产物隔离、浏览器回归与生产依赖审计。

最新本地单元回归 133 项通过；最近一次浏览器回归 55 项通过，覆盖桌面、手机、中英文和深浅色。格式、类型、构建及公开产物隔离检查通过，生产依赖审计未发现已知漏洞。独立审查复核了来源字段、公开名单、缓存、EdgeOne 接口与前端退避，并补充并发请求、部分失败和高频故障历史复查；修复均经过失败复现和回归验证。

配置调整新增 7 项真实生成器测试：实际配置优先、缺失时回退默认、显式路径优先，以及无效或无法读取时拒绝构建。原示例保存在 `config/default.json`，用户可提交 `config/site.json`；本次不改页面交互，未重复浏览器回归。

收尾新增真实函数入口集成测试，覆盖环境变量、节点缓存、可选 KV 及存储故障降级；HTTP 验收器自身覆盖正常、版本不符、旧快照、错误 MIME、资源缺失和只读边界。`pnpm run verify:deployment` 可对实际预览地址执行检查，具体条件见[部署指南](deployment.md)。这些本地测试使用受控上游，不能证明真实来源或平台行为。

本地预算样例（不包含网络等待）：50 个监控各 1440 个原始响应点，归一化、契约校验和序列化合计约 435ms / 8MB；改为首页各 48 个聚合点后约 33ms / 283KB。单个监控 1440 点详情约 14ms / 159KB。这是本机测量，不能保证 EdgeOne 的实际 CPU 用量。

另测每 60 秒检查且频繁切换状态的单个监控：720 个成功采样和 720 个故障区间，归一化由约 292–302ms 降至 9–14ms，保留 1440 条历史记录。并发回归覆盖冷缓存的 12 个首页、详情及混合请求，以及失败重试、凭证和版本隔离；在途合并只作用于同一运行实例，不能代替跨节点的上游额度验证。
