# 发布检查

## 本地与 CI

- 格式、类型、单元 / 集成测试、浏览器回归和依赖审计通过，命令见[开发文档](development.md#验证)。
- 默认产物不含演示数据、编辑器或实际服务端配置；启用编辑器的产物仍不含实际服务端配置。
- 配置编辑器导出的 JSON 能通过同一份配置校验；编辑 / 导入不访问生产监控 API，退出恢复生产数据且不复用预览缓存。

## 真实部署

使用与部署一致的提交、配置、锁文件和构建变量执行[部署验收](deployment.md#部署验证)，并核对：

- 首页一次请求加载当前大分组，子组本地切换；数量、排序和公开范围与配置一致。
- 双来源详情的 24h / 7d / 30d、最新检查、周期、事件及可用证书信息与上游口径一致。套餐缺失、聚合与零值不被误判为实现错误。
- 深层路由刷新有效；手机布局、中英文、深浅色、菜单和 Toast 正常。
- 默认构建忽略 `configeditor=on`；启用构建仅在带参数时进入编辑模式，无参数仍请求真实数据。
- 开启 KV 时，在绑定空间核对新缓存记录；HTTP 200 和页面可用均不足以单独证明 KV 命中。

## 故障与性能

来源适配或缓存策略变更时，在独立预览环境验证以下场景，不在生产注入故障：

| 场景                           | 预期                                                        |
| ------------------------------ | ----------------------------------------------------------- |
| 未绑定 KV / KV 读写失败        | 实时取数仍可用，能够降级                                    |
| 来源故障或限流，已有有效旧快照 | 保留旧数据及更新时间，返回脱敏原因；刷新 / 重试有结果 Toast |
| 冷缓存且来源故障               | 返回可理解的脱敏错误，来源恢复后能重新取数                  |
| 来源状态页撤销成员             | 名单缓存到期后移除，详情与状态缓存不能绕过新公开范围        |
| 更改部署配置                   | 新版本不复用旧版本的公开数据                                |
| 更换 / 移除来源密钥            | 更换后不复用旧凭证的缓存；移除后返回配置错误                |

分别观察冷 / 热请求的 `Server-Timing`、来源请求数和平台调用记录，记录提交与环境；不能用单次热缓存、本地模拟延迟或其他部署的旧数据代表当前性能。Peekaping 请求量随监控数增长，UptimeRobot 长周期查询受历史保留和来源额度限制。

节点缓存能力取决于平台环境；部分预览环境的 Cache API 会拒绝写入。未启用 KV 的冷实例不保证有旧数据可回退。缓存、诊断与排错方法见[数据与接口](data-api.md)及[排错](troubleshooting.md)。
